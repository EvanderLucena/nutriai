# Phase 07 — Wave 4: IA Meal Suggestion Refinement

## Status
**Inserido como wave extra da Phase 07** (não inicialmente planejado, emergiu da discussão com founder)
**Prioridade:** Alta — é o core value proposition do NutriAI
**Nota:** A ser executada em branch separada (ex: `feat/07-ia-meal-suggestion`)

---

## Contexto

A Wave 3 completou o pipeline WhatsApp (webhook, extração, timeline, E2E). Porém, durante review UAT conceitual, identificamos que o prompt da IA **não está instruído a sugerir refeições baseadas no horário** quando o paciente pergunta "Tô com fome, o que como?". Essa capacidade é central ao diferencial do NutriAI: "a IA responde ao paciente via WhatsApp usando o plano como base".

---

## Goal

O que deve ser TRUE após esta wave:

1. A IA consegue receber "Tô com fome" e sugerir refeição do plano baseada na hora atual
2. A IA pergunta "o que você tem disponível?" se paciente quiser algo fora do plano
3. A IA faz redução de danos (harm reduction): nunca reprova, sempre sugere preparação mais leve
4. O nutricionista vê na timeline que a mensagem foi classificada como "sugestão", não "refeição extraída"
5. Testes validam qualidade das respostas para 5+ cenários de sugestão

---

## Decisoes de Design

### D-01: Novo Intent `MEAL_SUGGESTION`

Hoje a IA classifica em:
- `MEAL_REPORT` — paciente relatou o que comeu
- `PLAN_QUESTION` — pergunta sobre o plano
- `GREETING` — saudação
- `MISCELLANEOUS` — outro

**Adicionar:** `MEAL_SUGGESTION` — paciente pede sugestão do que comer.

Motivação: sugestão não deve gerar `MealExtraction` na timeline. É uma interação de "perguntar/responder", não de "registrar refeição". A timeline só mostra refeições EXTRAÍDAS (quando o paciente diz "comi X").

### D-02: Horário atual no prompt

O prompt deve incluir a hora atual do servidor no formato pt-BR (ex: "11:30") para que a IA possa decidir "almoço está próximo" vs "já passou do café da manhã".

Formato no prompt:
```
Hora atual: 11:30
```

### D-03: Regra de sugestão baseada em horário

Instrução para a IA:
```
Se o paciente pedir sugestão do que comer:
1. Use a HORA ATUAL para encontrar a refeição do plano MAIS PRÓXIMA
2. Sugira PRIMEIRO uma opção do plano (ex: "Seu almoço programado é 12:30 com arroz e frango. Quer adiantar?")
3. Se o paciente disser que não quer nada do plano, PERGUNTE: "O que você tem disponível?" 
4. Com base na resposta, sugira:
   - Algo do plano que se aproxime (ex: se tem arroz em casa → arroz do almoço)
   - Ou alternativa saudável (harm reduction)
```

### D-04: Resposta da IA nunca gera extração

Mensagens classificadas como `MEAL_SUGGESTION`:
- NÃO chamam `extractionService.extractAndSave()`
- NÃO geram `EpisodeHistoryEvent` tipo `MEAL_EXTRACTION`
- Geram `EpisodeHistoryEvent` tipo `AI_SUGGESTION` (novo tipo) ou nada (apenas conversa)

**Decisão:** Gerar `AI_INTERACTION` genérico no history para registro de que houve conversa, mas sem dados estruturados.

### D-05: Redução de danos (Harm Reduction) em sugestões

Quando fora do plano, a IA deve:
- Sugerir preparação mais leve (grelhado > frito)
- Sugerir controle de porção ("meia porção")
- Evitar molhos, frituras, açúcar
- NUNCA dizer "isso não está no plano"
- SEMPRE dizer "pode ajustar a próxima refeição para compensar"

**Mudanças:**

### Task 4: E2E — Validação de qualidade da sugestão

**Arquivos:**
- `frontend/e2e/whatsapp-suggestion.spec.ts` (novo)

**Cenários:**

## Riscos

| Risco | Mitigação |
|-------|-----------|
| LLM alucina sugestão absurda | Prompt bem instruído + limitar a contexto do plano |
| IA sugere algo fora do plano sem redução de danos | Regras explícitas no prompt + teste de regressão |
| Performance: prompt fica grande com plano completo | Plano já é enviado hoje, não muda |
| Custo LLM aumenta | Sugestão é 1 call por mensagem (igual a extração), não muda volume |
