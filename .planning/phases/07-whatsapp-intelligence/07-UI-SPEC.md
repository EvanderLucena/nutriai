## Layout Specifications

### 1. PatientView — WhatsApp Activation Row

**Position:** Between the patient header stats row and the tab bar. After `patient-header-stats-row` closing `</div>` (line ~261 of PatientView.tsx) and before `patient-tab-row` opening `<div>` (line ~263).

**Layout:** Single horizontal row, 100% width, top border matching `var(--border)`, padding `10px 28px`.

```
┌──────────────────────────────────────────────────────────────────┐
│  [IconWhatsapp 16px]  WhatsApp: Ativado  ●  [Copiar link]       │
│  [IconWhatsapp 16px]  WhatsApp: Não ativado  ○  [Gerar link]    │
└──────────────────────────────────────────────────────────────────┘
```

**Specification:**
- Padding: `8px 28px` (total row height 38px: 8px top + 22px content + 8px bottom — all multiples of 4)
- Font size: 13px for status text (matches body size in typography table)
- Status dot: 8px diameter, green (`var(--sage)`) when activated, gray (`var(--fg-subtle)`) when not
- Gap between icon and text: 8px
- Gap between status dot and button: 16px (spacer)
- Button: `btn btn-ghost`, font-size 11px, padding `4px 8px`

**When `Patient.whatsapp` is NULL:**
- Row shows: "WhatsApp: Número não cadastrado — Cadastre o WhatsApp do paciente para ativar"
- Button label: "Editar paciente" → opens EditPatientModal

### 2. PatientView — Timeline (Today Tab)

**No layout changes.** The existing timeline structure (4-column grid: 70px time | 20px dot-line | 1fr content | 170px macros) is preserved. The only change is data source: `patient.timeline` (hardcoded `[]`) → `useExtractions(patientId)` API fetch.

**Layout reference (from existing Timeline.tsx):**
- Grid: `gridTemplateColumns: '70px 20px 1fr 170px'`
- Gap: 14px
- Row padding: 18px 22px
- Dot marker: 12px diameter, `var(--lime-dim)` background, 2px border, 3px box-shadow glow
- Connector line: 1px wide, `var(--border)` color, runs between dots

### 3. HomeView — WhatsApp KPIs

**Position:** Within the existing KPI grid. The current grid has 4 KPIs in a single row.

**Two options — executor chooses:**

| Option | Grid | KPI 1 | KPI 2 | KPI 3 | KPI 4 | KPI 5 | KPI 6 |
|--------|------|-------|-------|-------|-------|-------|-------|
| A (recommended) | 6 columns | Pacientes ativos | Adesão média | Avaliados 30d | Sem registro >3d | Refeições extraídas hoje | Pacientes WhatsApp |
| B | 4 + 2 | Pacientes ativos | Adesão média | Avaliados 30d | Sem registro >3d | — | — |
| | row 2 | Refeições extraídas hoje | Pacientes WhatsApp | — | — | — | — |

**Preferred: Option A** — 6 KPIs in one row with `gridTemplateColumns: 'repeat(6, 1fr)'` and `gap: 12` (tightened from 14 to fit).

**WhatsApp KPI 1 — "Refeições extraídas hoje":**
- Uses existing `KPI` component
- Value: integer count from WhatsApp extractions today
- Sub: "via WhatsApp"
- Uses `IconMeal` or `IconWhatsapp` as KPI icon prop
- Color: default `var(--fg)` (not danger)

**WhatsApp KPI 2 — "Pacientes ativos no WhatsApp":**
- Uses existing `KPI` component
- Value: integer count of patients with ≥1 WhatsApp message ever
- Sub: "ativaram WhatsApp"
- Uses `IconWhatsapp` as KPI icon prop
- Color: default `var(--fg)` (not danger)

**Empty state for WhatsApp KPIs (when 0):**
- Value: "0"
- Sub text unchanged — the zero itself communicates the state

### 4. ExtractionEditor (correction modal)

**No layout changes.** The existing inline editor panel is preserved:
- Margin: `0 22px 18px 106px` (indented under the timeline event)
- Background: `var(--surface-2)`
- Border: `1px solid var(--border)`, border-radius 8px
- Grid: `gridTemplateColumns: '2fr 0.7fr 0.7fr 0.7fr 0.7fr 28px'`
- Gap: 8px

**The only change:** `Salvar correção` button calls `patchExtraction.mutate()` instead of just closing.

## Interaction Contract

### 1. WhatsApp Activation Flow

```
State: PatientView loads
  │
  ├─ Patient.whatsapp IS NULL ──────────────────────────────┐
  │  Render: "WhatsApp: Número não cadastrado"              │
  │  CTA: "Editar paciente" → opens EditPatientModal        │
  │                                                          │
  └─ Patient.whatsapp EXISTS ───────────────────────────────┤
     │                                                       │
     ├─ isActivated === TRUE (≥1 WhatsApp message sent) ────┤
     │  Render: "WhatsApp: Ativado" + green dot             │
     │  CTA: "Copiar link"                                  │
     │  onClick: fetch activation-link API → copy to        │
     │           clipboard → toast "Link copiado!"          │
     │                                                       │
     └─ isActivated === FALSE ──────────────────────────────┤
        Render: "WhatsApp: Não ativado" + gray dot          │
        CTA: "Gerar link"                                   │
        onClick: fetch activation-link API → copy to        │
                 clipboard → toast "Link copiado!"          │
```

**Copy-to-clipboard pattern:**
```ts
navigator.clipboard.writeText(link).then(() => {
  toastStore.show("Link de ativação copiado!");
});
```

### 2. Timeline Data Loading

```
State: TodayTab mounts
  │
  ├─ LOADING ──────────────────────────────────────────────┐
  │  Show: timeline skeleton or subtle spinner              │
  │  (executor: can use "Carregando extrações..." text      │
  │   matching PatientView loading pattern, line 132)       │
  │                                                          │
  ├─ SUCCESS + extractions.length === 0 ───────────────────┤
  │  Show: existing empty state (Timeline.tsx:14-42)        │
  │  "Nenhum registro hoje" + explanation body              │
  │                                                          │
  ├─ SUCCESS + extractions.length > 0 ─────────────────────┤
  │  Show: timeline with extraction events                  │
  │  Each event: time, meal label, items list, macros       │
  │  "Corrigir extração" toggle per row                     │
  │                                                          │
  └─ ERROR ────────────────────────────────────────────────┤
     Show: error message "Erro ao carregar extrações."      │
     Offer: retry button or auto-retry via TanStack Query   │
```

**Loading state recommendation:** Use the existing PatientView loading pattern (line 132: centered text "Carregando extrações..."). Do NOT use skeleton UI — match the established convention.

### 3. Extraction Correction Flow (existing UI, new API wiring)

```
State: User clicks "Corrigir extração" on a timeline row
  │
  ├─ Opens ExtractionEditor inline (already exists)
  │  User edits food items, macros
  │  Live totals recalculate (already exists: ExtractionEditor.tsx:29-37)
  │
  ├─ User clicks "Salvar correção" ────────────────────────┐
  │  OPTIMISTIC UPDATE:                                     │
  │    1. Immediately close editor (`onClose()`)            │
  │    2. Update TanStack Query cache with corrected data   │
  │    3. Fire PATCH request in background                  │
  │    4. On success: toast "Extração corrigida com         │
  │       sucesso." + invalidate extractions query          │
  │    5. On error: rollback cache + toast error message    │
  │                                                          │
  └─ User clicks "Cancelar" ───────────────────────────────┘
     Close editor, no API call
```

**PATCH payload format:**
```typescript
interface PatchExtractionPayload {
  items: Array<{
    name: string;
    kcal: number;
    prot: number;
    carb: number;
    fat: number;
  }>;
}
```

### 4. Dashboard KPI Loading (WhatsApp data)

TanStack Query hooks for WhatsApp KPIs follow the same pattern as existing dashboard hooks:
- `useWhatsAppStatus()` — fetches `GET /api/v1/whatsapp/status`
- Loading state: KPI shows "..." (matching existing KPI loading)
- Error state: KPI shows "—" with sub "indisponível"
- Zero values: KPI shows "0" (normal state — not an error or empty state)
- Stale time: 30 seconds (WhatsApp data can be slightly behind, no need for real-time)

### 5. Toast Integration

All toasts use the existing `toastStore` pattern:
- Import: `import { useToastStore } from '../stores/toastStore'`
- Success toasts: auto-dismiss after 3 seconds
- Error toasts: auto-dismiss after 5 seconds, or with a "Tentar novamente" action

## Accessibility

### Minimum Requirements

| Requirement | Implementation |
|-------------|---------------|
| **Activation button** | `<button>` element with accessible name ("Copiar link de ativação" / "Gerar link de ativação") |
| **Copy confirmation** | Toast provides text feedback; also use `aria-live="polite"` region for screen readers |
| **Status dot** | Must have `role="img"` and `aria-label` ("WhatsApp ativado" / "WhatsApp não ativado") |
| **Timeline entries** | Time and meal labels must be readable by screen readers in logical order (existing structure is fine) |
| **ExtractionEditor inputs** | All inputs must have associated labels. Existing `eyebrow` column headers serve this role via `aria-labelledby` or visible labels |
| **Color contrast** | All `--fg-muted` text (#6B6F62) on `--surface` (#FEFCF6) = contrast ratio ~5.2:1 ✓ |
| **Keyboard navigation** | Tab through timeline rows → "Corrigir extração" button focusable → ExtractionEditor inputs focusable → Esc closes editor |
| **Focus management** | When ExtractionEditor opens, focus the first input field. When it closes, return focus to the "Corrigir extração" button |
| **Loading states** | Use `aria-busy="true"` on loading regions. Announce completion with `aria-live` |

### Accessibility Notes for Executor

1. **Activation row status dot:** Both the green dot and gray dot must have `aria-label` set to "WhatsApp ativado" or "WhatsApp não ativado." These are informational images, not decorative.
2. **Copy-to-clipboard:** Since the clipboard action is invisible to screen readers, the toast + `aria-live` region must announce "Link copiado."
3. **Timeline empty state:** The existing empty state uses a 🍽️ emoji. Add `aria-hidden="true"` to the emoji `<span>` since it's decorative-only (the text below already explains the state).
4. **KPI cards:** Each KPI card already functions as a presentational element — no interactive behavior. No changes needed.
