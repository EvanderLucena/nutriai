## Objective

Polish the frontend to eliminate remaining UX rough edges before WhatsApp Intelligence (Phase 07). Focus on empty states, validation consistency, and E2E coverage for critical clinical flows.

## Wave 1 — Empty States & UX Honesty

1. **TodayTab empty state** — when patient.timeline is empty, show 'Nenhum registro ainda' instead of blank space
2. **HistoryTab empty state** — when snapshot.timelineEvents is empty, show friendly empty state
3. **PlanTab empty state** — when no meal plan exists, show 'Plano nao configurado' with CTA to create
4. **Loading states consistency** — standardize skeleton/loading across all PatientView tabs
5. **Error states** — when API fails, show retry button instead of static text

## Wave 2 — Validation & Form Polish

6. **NewPatientModal** — adopt useValidation hook (currently manual validation)
7. **NewBiometryModal** — add clinical bounds validation via useValidation:
   - weight > 0, height 50-250, bodyFat 0-100, visceralFat integer
8. **AddFoodModal / EditFoodModal** — prevent Number(value) || 0 silent conversion
9. **Consolidate patient modals** — deduplicate New/Edit patient logic if divergence exists

## Wave 3 — E2E Critical Flows

10. **E2E: Biometry -> Dashboard** — create assessment via UI, verify dashboard KPI update
11. **E2E: Food -> Plan** — create food, add to plan, edit quantity, verify macro update
12. **E2E: Patient lifecycle** — create -> edit -> deactivate -> reactivate -> delete

## Success Criteria

- [ ] All PatientView tabs show explicit empty states (not blank)
- [ ] All forms use useValidation with consistent pt-BR messages
- [ ] Biometry validation enforces clinical bounds
- [ ] Food/plan numeric inputs reject invalid values (not silently convert to 0)
- [ ] 3 new E2E flows pass in CI
- [ ] npx tsc --noEmit passes
- [ ] E2E suite passes
